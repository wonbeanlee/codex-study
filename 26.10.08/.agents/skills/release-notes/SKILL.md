# 릴리스 노트 작성

## 단계
1. `.agents/skills/release-notes/scripts/last_tags.sh`를 실행해 마지막 태그 이후의 커밋을 한 줄씩 확인한다. 태그가 없으면 전체 커밋 목록을 확인한다.
2. 변경을 새 기능, 버그 수정, 개선, 문서로 분류한다.
3. 사용자 관점의 문장으로 다시 쓴다. 내부 용어는 지양한다.
4. 아래 형식으로 출력한다.

## 출력 형식
## vX.Y.X (YYYY-MM-DD)
### 새 기능
- ...
### 버그 수정
- ...

## 규칙
- 사용자에게 의미 없는 변경(예: 내부 리팩터링)은 생략하거나 묶는다.
- 한국어로 간결하게 작성한다.
